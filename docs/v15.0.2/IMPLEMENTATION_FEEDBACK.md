# 蜉蝣基金（FundVal）v15.0.2 实施反馈

## 目标与范围

本补丁集中收敛 v15.0.1 审计发现的四组可靠性风险：行情日期与盈亏基期、持仓并发事务、支付宝长截图 OCR，以及隔离行情 Bridge 的请求调度。除将 PaddleOCR 的间接依赖 `js-yaml` 从 4.3.1 更新至修复高危漏洞的 4.3.2 外，不升级 OCR 引擎或模型；不改变 Schema 3 格式、不上传截图，也不把模拟器或合成测试写成物理设备验收。

完整修复证据见 `../REPAIR_STATUS_2026-09-23.md`，机器可读性能样本见 `../REPAIR_PERFORMANCE_2026-09-24.json`。

## 实现摘要

- Quote Envelope 绑定 `baseNav/baseNavDate/targetDate`，正式净值按日期择新；盈亏只使用被选中 Quote 自己的基期。
- 海外模型要求基期后一交易日的同一市场会话，拒绝未来、过期、混日或跨多日单日涨幅。
- 所有危险持仓写入在 Web Lock 内重读并做基线比较；保存成功后才更新页面，失败保留原数据和表单草稿。
- OCR 覆盖整张长截图，歧义候选默认跳过，缺失字段保留 `null`；清单、初始化、识别和销毁均可超时或取消。
- Bridge 将网络期限绑定到实际派发，队列可取消且有容量/总期限；活动请求失败时重建隔离 iframe。
- 诊断、导入导出与准确率模块拆为按需 chunk，维持既有冷启动预算。
